# SEZIONE — Services Page Research Brief

## Status
Gate 1 complete. Gate 2 visual concept complete. Gate 3 high-fidelity Figma complete. Waiting for Founder Gate A.

## Method
This page uses the Fairuz operating strategy as a process, not as a visual template:
1. Preserve what already works.
2. Research real user friction.
3. Improve practical clarity and conversion before decoration.
4. Benchmark strong category references without imitation.
5. Use approved/authentic imagery before generating new assets.
6. Do not invent trust signals or operating facts.
7. Prove desktop and mobile visually before implementation.
8. Code only after founder visual approval.

## Research signal
Reference patterns reviewed:
- Hershesons: consultation as a way to reduce uncertainty before colour booking.
- Josh Wood Colour: personalised consultation and pre-appointment guidance.
- Larry King: consultation tied to lifestyle, look and individuality.
- George Northwood: understandable service families rather than undifferentiated marketing language.

## User problem
The Services page must answer:
- Which type of service is relevant to me?
- Do I need a consultation / first-visit path?
- What is the difference between Cut, Color, Care and Styling?
- What do I do if I do not know the technical service name?
- What is the next clear action?

## Locked architecture
1. Services Hero — simplify the choice.
2. Decision layer — result, starting point, texture, maintenance.
3. Four service families:
   - Cut / Shape
   - Color / Tone
   - Care / Repair
   - Finish / Styling
4. First Visit — decision support for uncertain users.
5. How We Choose — base, texture, maintenance and routine.
6. Final CTA — direct booking + first-visit alternative.
